# 7. 데이터 디스크 마운트

## 목적

HPC 노드에 **새 데이터(관리) 디스크**를 추가해 포맷하고 마운트하는 절차이다. 노드별 로컬 데이터 공간이 더 필요할 때 CycleCloud 템플릿의 `[[[volume]]]` 과 `cyclecloud.mounts.*` 로 선언적으로 붙인다. 
공유 파일시스템(NFS, Lustre), Azure Files, Blob, Locker 마운트는 [8. 스토리지 마운트](08-스토리지-NFS-마운트.md)를 참고한다.

## 사전 조건

- CycleCloud 클러스터와 대상 HPC 노드에 접속할 수 있어야 한다.
- 클러스터 템플릿(`slurm.txt`)과 `cyclecloud` CLI(`export_parameters`/`import_cluster`)를 사용할 수 있어야 한다.
- OS(부팅) 디스크 크기 변경은 [9. 디스크 사이즈 변경](09-디스크-사이즈-변경.md)을 참고한다.

---

## 절차

### 7.1 새 데이터 디스크(관리 디스크) 추가 및 마운트

- 노드에 로컬 데이터 공간이 더 필요하면 **관리 디스크(Managed Disk, CycleCloud 용어로 volume)** 를 추가로 붙여 마운트한다. CycleCloud는 디스크 연결과 포맷, 마운트를 **노드가 시작되는 시점**에 처리한다.
- **볼륨 추가는 실행 중 노드에 자동 반영되지 않는다** - `[[[volume]]]` 선언은 **새로 시작하는 노드**에만 적용된다. 볼륨은 scaleset 속성이라, 일부 노드만 재생성하면 `This node does not match existing scaleset attributes: Volumes.*` 오류로 거부된다.
- **실행 중 array 에 반영하려면 해당 nodearray 전체를 내렸다가 올려** 옛 scaleset 을 삭제한 뒤 다시 만들어야 한다.
- OS(부팅) 디스크 **크기 변경**은 새 디스크 추가가 아니라 기존 디스크 확장이므로 [9. 디스크 사이즈 변경](09-디스크-사이즈-변경.md)을 참고한다.

템플릿의 `[[node]]` 또는 `[[nodearray]]` 에 `[[[volume]]]`(디스크 연결)과 `Mount`, `[[[configuration cyclecloud.mounts.<name>]]]`(포맷, 마운트)을 함께 정의한다. `[[[volume]]]` 만 있으면 디바이스만 연결되고, `Mount` 를 지정해야 시작 시 포맷되어 마운트된다. 이 선언들은 `[[[configuration]]]` 의 **일반 속성 뒤, 첫 `[[[cluster-init` 앞**에 넣는다.

```ini
[[nodearray hpc]]
    ...
    [[[volume datadisk]]]
    Size = 128                       # GB
    StorageAccountType = Premium_LRS # 또는 SSD = true
    Mount = data                     # 아래 마운트 구성 이름과 연결
    Persistent = false               # nodearray(VMSS)에서는 반드시 false. true 는 단독 [[node]] 전용

    [[[configuration cyclecloud.mounts.data]]]
    mountpoint = /mnt/data
    fs_type = xfs                    # ext3 / ext4 / xfs
```

- **`Persistent = true` 는 단일 노드(`[[node ...]]`) 전용이다.** `[[nodearray ...]]` 는 VMSS 로 뜨는데, VMSS 는 모든 인스턴스가 **하나의 모델을 공유**하므로 특정 디스크를 지목해 계속 붙여 쓰는 영속 볼륨을 표현할 수 없다. 지정하면 노드 기동 시 `Scaleset disk '<이름>' cannot be persistent` 로 실패한다.

  | 넣는 위치 | VMSS 여부 | `Persistent = true` |
  |---|---|---|
  | `[[node nodearraybase]]` | 상속하는 것이 전부 nodearray | ❌ |
  | `[[nodearray hpc]]` / `htc` / `gpu` | VMSS | ❌ |
  | `[[node scheduler]]` | 단독 VM | ✅ |
  | `[[node mynode]]` ([3-1장](03-1-싱글-노드-배포.md)) | 단독 VM (`Extends = nodearraybase` 여도) | ✅ |

  갈림길은 상속이 아니라 **`node` 냐 `nodearray` 냐**다. 계산 노드는 매번 새로 뜨므로 디스크를 남겨도 다시 붙지 않는다 — 계산 노드에서 데이터를 유지해야 하면 디스크가 아니라 [NFS](08-스토리지-NFS-마운트.md) 를 쓴다.
- 단일 노드에서 `Persistent = true` 이면 인스턴스가 종료돼도 볼륨을 유지하고 다음 시작 때 재부착한다(클러스터 삭제 시에만 삭제).
- 기존 디스크 재사용은 `VolumeId = <disk-id>`, 여러 볼륨 RAID는 `raid_level`, 암호화는 `DiskEncryptionSetId` 를 사용한다.

> 📋 **바로 붙여넣어 쓸 수 있는 예시 템플릿 조각**: [`templates/add-disk.txt`](../templates/add-disk.txt) — `[A] 신규 디스크 생성 + 마운트`, `[B] 기존 디스크(VolumeId) attach + 마운트` 두 시나리오를 담고 있다. 붙여넣는 위치와 반영 방법은 파일 상단 주석을 참고한다.

**적용 절차**

1. 템플릿 수정 후 재적용한다.

   ```bash
   cyclecloud export_parameters <클러스터명> > params.json
   cyclecloud import_cluster <클러스터명> -c Slurm -f slurm.txt -p params.json --force
   ```

2. 해당 nodearray 의 **모든 노드를 내렸다가** 다시 올린다. 일부만 재생성하면 scaleset 불일치로 실패한다.

   ```bash
   # 모든 노드를 내림 → 옛 scaleset 삭제 (GUI Scalesets 탭에서 사라졌는지 확인)
   azslurm suspend --node-list <클러스터명>-hpc-[1-4]
   azslurm resume  --node-list <클러스터명>-hpc-[1-4]
   ```

   CycleCloud 가 파티션과 포맷, `fstab` 을 처리하므로 노드별 수동 작업은 필요 없다.

## 검증

- 노드에서 `lsblk` / `df -h <마운트경로>` 로 디스크가 붙었는지 확인한다.
- 마운트 지점에 테스트 파일 읽기/쓰기가 정상인지 확인한다.
- VMSS 배열 전체를 recycle한 경우 `sinfo` 로 노드가 idle 상태로 복귀했는지 확인한다.

## 롤백·주의

- `[[[volume]]]` 선언이나 제거는 **새로 시작하는 노드**부터 반영된다. 실행 중 array 는 전체를 재생성해야 한다.
- `Persistent = true` 볼륨은 노드 종료 후에도 유지되며 **클러스터 삭제 시에만** 삭제된다. 단, **단독 `[[node]]` 에서만 지정할 수 있다** — nodearray 에 넣으면 `Scaleset disk '<이름>' cannot be persistent` 로 노드 기동이 실패한다.
- 실행 중 nodearray 에 볼륨을 추가하면 scaleset 속성 불일치가 발생하므로 해당 배열을 **전부 recycle** 해야 한다(§7.1 참고).
